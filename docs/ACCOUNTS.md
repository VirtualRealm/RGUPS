# Аккаунты и личный кабинет

Реализовано 12.10.2026. Это рабочий серверный модуль собственного портала. Подключения к реальной университетской базе пользователей и переноса Moodle пока нет.

## Запуск без Docker

Требуются Node.js 24.7+ и pnpm 11.25.0. Из корня проекта:

```sh
pnpm install --frozen-lockfile
pnpm dev:local
```

Если DATABASE_URL не задан, скрипт создаёт постоянную локальную PGlite, применяет миграции, заполняет справочники и запускает http://127.0.0.1:3000. База, случайный пароль и тестовая почта сохраняются в игнорируемой `.local/`; не отправляйте эту папку другим людям. PGlite предназначена для разработки. Ctrl+C завершает процессы и сохраняет базу; повторный запуск сохраняет аккаунты.

При наличии DATABASE_URL в окружении или `.env` используется указанная база. Не задавайте рабочую университетскую БД для экспериментов: скрипт применяет миграции. Порты: PORTAL_PORT и PORTAL_DB_PORT. После аварийного завершения lock-файл можно удалить только после проверки, что его PID больше не работает; папку данных удалять не нужно.

## Показ регистрации

1. Откройте `/registration`, выберите студента или преподавателя, заполните анкету и задайте пароль от 12 символов.
2. Студент выбирает группу из БД и указывает номер билета. Преподаватель создаёт заявку; роль автоматически не выдаётся.
3. Откроется кабинет с ожиданием проверки. Локальное письмо находится в `.local/mail/*.json`: откройте поле `url` в браузере и подтвердите e-mail. Письма наружу не отправляются.
4. Администратор сверяет принадлежность с университетским реестром и рассматривает заявку в `/admin/accounts`. Преподаватель привязывается к официальному справочнику и записи расписания.
5. Подтверждения почты недостаточно для учебного доступа. Статус и действующие роли всегда проверяются на сервере.

Первого администратора назначает оператор БД:

```sh
pnpm accounts:admin operator@example.org --grant-admin
```

Аккаунт должен уже существовать и подтвердить e-mail. Команда журналирует назначение и отзывает прежние сессии. После неё необходимо войти снова. Не назначайте администратором случайного заявителя. При автоматической локальной базе команда читает `.local/dev-db/connection.json`, если DATABASE_URL не задан.

## Сессии и восстановление

- «Запомнить устройство»: cookie на 30 суток с абсолютным сроком. Без флажка cookie сессионная, серверный срок 12 часов. Восстановление вкладок браузером может сохранять сессионные cookie; на общем компьютере нажимайте «Выйти».
- HttpOnly, SameSite=Lax, Secure и префикс `__Host-` при HTTPS; без общего Domain со старым Moodle. В localStorage нет паролей или токенов.
- В БД только SHA-256 случайного 256-битного session token. Название браузера/ОС, дата и текущая сессия доступны владельцу; можно закрыть один вход или все остальные. Fingerprinting не используется.
- Смена пароля проверяет старый, отзывает прочие сессии и ранее выданные ссылки сброса. Восстановление закрывает все сессии. Одноразовые ссылки: подтверждение 24 часа, восстановление 1 час; в БД только хеш. Токен передаётся во fragment и погашается POST после явного действия.
- Argon2id: 64 MiB, 3 прохода, parallelism 1, соль 16 байт. Никаких паролей из номера билета.
- Мутации требуют точный APP_URL Origin, JSON, специальный заголовок; тело до 16 KiB. Серверная Zod-валидация отвергает произвольные role/userId.
- Лимиты привязаны к аккаунтам/пользователям. TRUST_PROXY=1 добавляет ограничение по X-Real-IP только за доверенным reverse proxy, который перезаписывает этот заголовок и закрывает прямой доступ к Node. Выход и отзыв сессий не блокируются общим сетевым лимитом.

## Кабинеты

Отдельные страницы `/dashboard/*`, адаптивное меню, загрузка, ошибки и пустые состояния. Студент: группа, календарь, следующая пара, дисциплины, свои оценки/задания, уведомления, профиль, устройства. Преподаватель: связанное расписание, группы, назначенные дисциплины, число работ на проверку и профиль.

Расписание ВО — подтверждённый публичный снимок от 11.10.2026. Курсы, оценки, задания и уведомления читаются из собственной БД с проверкой владельца и назначения. Демонстрационные оценки в реальный кабинет не подставляются. Редактор курсов, загрузка файлов, сдача работ, тестирование, выставление оценок и CMS относятся к следующим модулям LMS.

## Сервер и демонстрация

Полная последовательность размещения и назначения первого администратора — [DEPLOYMENT.md](DEPLOYMENT.md). `compose.production.yaml` включает отдельный шаг миграций, проверку SMTP, PostgreSQL и Caddy с HTTPS. `pnpm check:production` проверяет обязательные настройки, `pnpm check:services` проверяет соединения без отправки писем.

Обычный `pnpm build` создаёт Next.js standalone. Для размещения нужны PostgreSQL, HTTPS и SMTP; настройки в `.env.example`. Выполните `pnpm db:generate`, `pnpm db:deploy`, `pnpm db:seed`. APP_URL точно совпадает с HTTPS-адресом сайта; MAIL_MODE=smtp. Пароль в DATABASE_URL должен быть URL-encoded; стандартный compose подходит для пароля из букв, цифр и дефисов. Контейнеры в текущей среде не проверялись.

Хостинг `chatgpt.site` у этого проекта статический: Node/PostgreSQL API на нём не запущен. `pnpm build:public` создаёт изолированный предпросмотр без серверных маршрутов; `pnpm build:offline` собирает один HTML. В этих версиях нет реальной регистрации или сохранения личных данных. Для публикации настоящих аккаунтов нужен отдельный сервер и SMTP.

Проверки: lint, typecheck, test, build. `pnpm test:accounts` запускается при работающем локальном приложении с MAIL_MODE=local; использует вымышленные example.invalid аккаунты и удаляет только свои записи. Перед использованием реальных студенческих данных остаются ручная проверка UI, PostgreSQL/Docker, SMTP-доставка, резервное копирование и эксплуатационный аудит.
