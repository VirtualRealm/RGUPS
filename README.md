# РГУПС · Воронеж — цифровой портал

Реализованы публичный портал, официальные справочники, регистрация студентов и преподавателей, сохраняемый вход и отдельные страницы личного кабинета. Серверная версия работает с собственной PostgreSQL-базой; к реестру университета и Moodle она пока не подключена. Полная LMS — следующий этап.

Текущий выпуск: **1.0.0-rc.1**. Регистрация проверена локально; рабочий HTTPS-сервер и доставка писем ещё не развёрнуты. Инструкция размещения с PostgreSQL, миграциями и HTTPS: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Репозиторий: [VirtualRealm/RGUPS](https://github.com/VirtualRealm/RGUPS).

## Что работает

- Главная, временный SVG wordmark, единая навигация и footer.
- Новости: карточки, отдельные страницы, поиск, рубрики и пагинация; пересказы реальных материалов со ссылками и один демонстрационный материал.
- Преподаватели: 102 уникальных профиля из 258 строк 17 официальных реестров; поиск по ФИО, дисциплине, специальности; фильтры ВО/СПО; квалификация, опыт, повышение квалификации и назначения по программам.
- Расписание: 4 400 опубликованных занятий ВО, день/неделя, группа/преподаватель/аудитория, очная/заочная форма. Проверены 365 дат учебного года и 96 заочных сессий 32 потоков. 38 замен СПО на 9, 10 и 12 октября, 9 локальных PDF. Основное расписание СПО пока недоступно: все 12 вариантов официальной формы возвращают пустую страницу. Снимок от 11.10.2026 не обновляется автоматически.
- Образование: ВО — 2 очные специальности («Эксплуатация железных дорог», «Строительство железных дорог, мостов и транспортных тоннелей») и 4 заочные; СПО — 8 профилей по 7 специальностям в плане приёма 2026. Также 2 программы прежних наборов; отдельные страницы, формы, сроки, места, квоты, источники.
- Поступление: документы ВО/СПО, минимальные баллы, 4 календаря, условия конкурса и зачисления, квоты, медосмотр, общежитие, приёмные комиссии и полные правила 2026.
- Руководство: 3 руководителя филиала, 8 представителей ректората, 20 органов управления и подразделений с опубликованными контактами и положениями.
- Дополнительное образование: поиск, категории, страницы направлений, контакты ЦДО.
- Страницы университета, поступления, студента, документов, контактов с картой, источников.
- Регистрация студента/преподавателя, подтверждение e-mail, проверка принадлежности администратором, вход, восстановление и смена пароля. Argon2id, серверные отзываемые сессии, сохранение устройства на 30 дней.
- Отдельные страницы кабинета: обзор, расписание, дисциплины, зачётная книжка, задания/работы на проверку, группы преподавателя, уведомления, профиль и устройства. Учебные данные читаются только в рамках прав текущего пользователя.
- Административная страница проверки аккаунтов и привязки преподавателя к официальному справочнику/расписанию.
- Loading, 404, компонент ошибки 500, экран 403; клавиатурный focus и reduced-motion.

## Запуск

Нужен Node.js 24.7+ и pnpm 11.25.0.

```sh
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
pnpm dev:local
```

Открыть http://127.0.0.1:3000. Без DATABASE_URL автоматически запускается постоянная локальная база PGlite, применяются миграции и seed. Аккаунты сохраняются между запусками. Письма для проверки находятся в `.local/mail/*.json`; отправки наружу нет. Подробный сценарий регистрации, назначения администратора, SMTP и production — [docs/ACCOUNTS.md](docs/ACCOUNTS.md).

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm test:accounts # при работающем локальном сервере
pnpm db:validate
pnpm build
```

`pnpm start` предназначен для настроенного production-окружения и перед запуском проверяет HTTPS, БД и SMTP. Для локального показа используйте `pnpm dev:local`.

## Автономная HTML-демонстрация

Готовый `rgups-portal-demo.html` находится рядом с папкой проекта. Откройте его двойным щелчком в современном браузере. Сервер, установка пакетов и интернет не нужны. Поиск, фильтры, страницы преподавателей, календарь, сессии, замены и PDF встроены в файл. Пример календаря для показа: ВДЖУ-241, 12 октября 2026; далее можно переключить «Неделя». Все исходные подтверждённые данные сохранены.

HTML содержит предпросмотр кабинетов и проверку демоформ, но не создаёт аккаунты. Для настоящей регистрации запускайте серверную версию. Внешние официальные сайты, почта и карты требуют подключения. Файл не содержит секретов и не сохраняет персональные данные. Примеры оценок в предпросмотре явно обозначены; в рабочий кабинет они не попадают.

Повторная сборка:

```sh
pnpm build:public
node scripts/check-export.mjs
node scripts/build-offline.mjs
node scripts/check-offline.mjs
```

Сборщик использует установленный вместе с `tsx` пакет esbuild. `offline/` содержит адаптеры изображений и ссылок, автономную навигацию и оболочку. Интерактивные страницы используют те же React-компоненты, что опубликованный портал; персональные страницы берутся из проверенного статического экспорта. CSS, JavaScript, фотографии и PDF встроены в один файл. Манифест рядом с HTML содержит число страниц, ресурсов и размер.

## PostgreSQL и Docker

Скопируйте .env.example в .env, измените пароль и DATABASE_URL согласованно. Настоящие секреты в Git не добавляются. Seed создаёт группы из опубликованных расписаний и категории — без аккаунтов или паролей; регистрацию обслуживает таблица Group.

```sh
docker compose up -d db
pnpm db:generate
pnpm db:deploy
pnpm db:seed
docker compose up --build app
```

Обычный build — standalone для Node.js/Docker. Dockerfile запускает приложение непривилегированным пользователем. Миграции выполняйте отдельно на целевой БД. Локальные миграции и seed проверены на PGlite; Docker и полноценный PostgreSQL-сервер в этой среде не проверены.

Статический предпросмотр: `pnpm build:public`, результат out/. Сборщик работает в отдельной временной папке и исключает серверный API. Private Sites и автономный HTML показывают публичную часть и демонстрационный кабинет. Настоящий auth backend требует Node.js/PostgreSQL-хостинга; официальный домен не меняется.

## Структура

```text
src/app/                 маршруты, metadata, layout, состояния
src/components/          оболочка, карточки, формы и фильтры
src/lib/                 общие данные, типы, поиск и пагинация
src/content/             проверенные снимки официальных справочников, ссылки и даты
src/server/auth/         аккаунты, сессии, почта, проверки доступа и API кабинета
src/server/policies/     общая матрица RBAC для будущих модулей
prisma/schema.prisma     нормализованная модель системы
prisma/migrations/       фундамент и миграция аккаунтов/устройств
prisma/seed.ts           повторяемое заполнение справочников
tests/                   тесты фильтров, дат, политик и криптографии
scripts/                 локальный запуск, проверка API, экспорт и offline HTML
public/                  фотографии, favicon, временный логотип
docs/                    архитектура и дизайн-система
deploy/nginx.conf        основа reverse proxy
Dockerfile, compose.yaml контейнерное окружение
```

## Решения и следующий этап

Модульный монолит; UI не зависит от БД. Course связан с Subject, несколькими преподавателями и группами. История членства в группах, множественные роли, токены активации и сессии — отдельные сущности. Доступ запрещён по умолчанию. Подробности в docs/ARCHITECTURE.md.

Осталось: редактор курсов, приём файлов/работ, тестирование и журнал преподавателя; полная CMS/админка; подключение SMTP/S3, официальной базы и перенос данных. Для эксплуатации нужны сервер/домен, TLS, реальные почтовые настройки, резервное копирование, мониторинг и ручная проверка адаптивности/доступности. Браузерные проверки были заблокированы политикой среды.

Проверки выполнения и ограничения: docs/VERIFICATION.md. Покрытие источников и порядок обновления: docs/CONTENT.md. Источники данных и авторство изображений видны на /credits. Старые сайты не изменены.
